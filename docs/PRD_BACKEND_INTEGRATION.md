# 角色资料采集工具后端接入 PRD
版本 1.0 评审稿 | 2026 年 10 月 26 日 | 原型基线 v1.13.1

## 1 项目目标与首版范围

本 PRD 面向产品、系统后端、采集器与插件开发。目标是把现有角色资料读取器接入业务系统，让使用者点击批量读取后，自动获得可用、去重、来源可追溯的角色资料，并在标记已使用后自动补货。本文是对接评审稿，尚未连接现有系统后端。

建议保留浏览器插件与采集 Worker，把任务、角色主记录、库存、反馈及审计统一交给后端。先打通一个工作空间的真实读取到补货闭环，再扩展渠道和部署方式。业务后端语言、数据库、登录方式、角色发布接口和部署环境均待确认。

使用者是负责选题与角色资料整理的运营人员。他们需要省去逐站复制、核对字段、查重复和手动找替补的工作。首版不增加收费或订阅设计。

| 当前已验证 | 证据与边界 |
| --- | --- |
| 本地原型 v1.13.1 | Python 本机 API、原生 JavaScript 页面与浏览器扩展；代码开源，业务后端尚未接入。 |
| 恢复后的库存 | 2026 年 10 月 26 日核对为 50 待用、5 备用、6 条使用记录；这是一次状态观察，不保证长期供给。 |
| 独立用户目录测试 | 此前一次从分发包启动，读取 60 份详情，自动入库 6 个，其中 3 个九项齐全；无人工确认，复用了本机模型依赖。 |
| 自动化边界 | 尚未完成另一台实体电脑的首次安装实测；未证明聊天质量达到 VL。VL 只作参考，不纳入采集。 |

| 优先级 | 首版交付 |
| --- | --- |
| P0 | 后端任务管理、公开或已授权来源读取、字段和头像入库、自动筛选、去重、50 加 5 库存、原子消费与补位、偏好与撤销、失败重试、跨工作空间隔离。 |
| P1 | 更多来源适配器、采集速度与质量优化、个人偏好、复杂运营报表。 |
| 不在首版 | 自动洗稿或补写作者设定、自动对外发布、绕过来源授权、把候选目录冒充完整角色、复制 VL 角色。 |

核心验证：一个没有原库存和反馈的新用户，能否在支持的来源可用时，独立完成启动任务、获取真实详情与头像、自动入库、使用一个再补一个。

## 2 系统职责与完整流程

推荐采用后端作为唯一业务状态来源，Worker 负责执行读取与图像检查，插件负责用户明确触发的页面读取或辅助授权。Worker 可以先部署在本机，接口稳定后再迁移到服务器；需要用户本机登录环境的来源仍由本机 Worker 执行，不把整份浏览器会话上传后端。

首版建议同一工作空间共享库存与偏好，跨工作空间完全隔离；每次操作记录操作者。是否改为个人偏好由业务方确认。任务和消费均复用现有系统的用户与工作空间身份。

原型已配置 Chub、BotBooru、CharaVault 的完整详情适配器；可读范围取决于来源公开响应。CrushOn、SpicyChat 目前只验证了公开候选目录，完整人设仍需授权；Janitor 尚未打通。后台应按渠道声明能力，不能把登录状态或目录成功当作完整读取成功。

| 组件 | 职责 | 不能承担的职责 |
| --- | --- | --- |
| 系统页面 | 发起读取，显示进度与角色，提交使用与偏好，复制和导出。 | 不在浏览器内计算最终库存或决定角色已使用。 |
| 系统后端 | 鉴权、任务租约、规范化主数据、库存事务、规则版本、去重、反馈与审计、媒体访问授权。 | 不相信客户端上报的最终库存和审核结果计数。 |
| 采集 Worker | 按适配器读取目录和完整详情，下载原图，执行规范化与图像检查，提交结果和证据。 | 不直接访问业务数据库；不持有所有租户的登录凭证。 |
| 浏览器插件 | 当前页面可见字段读取、显式触发的资料上传、与绑定用户的本机 Worker 配合。 | 不导出密码、Cookie、整个浏览器配置或隐藏私密字段。 |
| 来源适配器 | 提供目录、详情、头像及能力声明，返回来源真实分级与热度。 | 不将下载数伪装为点赞，不伪造作者未公开字段。 |

- 1 运营点击开始批量读取，后端保存任务、选定渠道、规则快照与幂等键，并立即返回任务编号。

- 2 Worker 获取可执行任务及租约，读取各渠道目录；按渠道、搜索词、排序方式与页码保存游标。

- 3 Worker 取得完整详情和头像，后端校验来源身份，规范化九项字段，保存原始证据与字段来源。

- 4 自动执行年龄、内容、人像、图像清晰度、热度、偏好与重复检查。通过进入可用集合，不通过保留原因；执行故障进入重试。

- 5 后端在事务中填充待用和备用；满库时合格角色等待补位，不能被计为已使用。

- 6 运营标记已使用，后端原子写入使用记录并优先用备用补位，随后触发补货。插件或网页关闭不取消后端已接收的任务。

## 3 角色数据与字段契约

九项业务字段必须在响应结构中始终存在，缺失值用 null，并列入 missing_fields。禁止为了完整率自动生成作者年龄、性别、Scenario、greet 或 prompt。来源原文与用户编辑版本分开保存，刷新来源时不得覆盖已确认的人工编辑。

| 字段 | 类型与取值 | 规则 |
| --- | --- | --- |
| category | 字符串数组 | 保存作者标签，运营分类另存；不混写。 |
| name | 字符串 | 保留来源名称，内部角色编号独立于名称。 |
| avatar | 媒体对象或 null | 含 media_id、原始 URL、摘要、审核状态和版本；页面通过后端媒体地址展示。 |
| gender | Female / Male / Non-binary / null | 仅采用作者明确字段或标签，不从名字或头像猜测。 |
| age | 字符串或 null | 允许作者原始年龄表示，成年判断另有证据字段。 |
| scenario | 字符串或 null | 保留作者原文；缺少时不从开场白反推。 |
| greet | 字符串或 null | 首条开场白；多开场另存 alternate_greetings。 |
| intro | 字符串或 null | 对外角色介绍，与人设提示词分别保存。 |
| prompt | 字符串或 null | 保留公开人设及原始字段结构，隐藏定义不得推断或标记为已读。 |

| 逻辑实体 | 必要信息 |
| --- | --- |
| Character 与 SourceRecord | 内部角色编号、工作空间、来源站与原站角色 ID、作者及链接、canonical_url、原始内容对象引用、九项字段、field_provenance、缺失项、版本与时间。 |
| Media 与 Screening | 文件摘要、大小与格式、可访问对象引用、来源版本、模型版本、规则版本、检查时间、结论与原因；审核必须绑定实际图片字节。 |
| Job 与 SourceCursor | 任务、执行者租约、心跳、规则快照、各渠道进度、错误、去重计数及可恢复游标。 |
| Inventory 与 Feedback | 待用和备用槽位、消费记录、操作者、反馈事件、作用范围、撤销关系及数据修订号。 |

热度指标分别保存 views、likes、favorites、downloads、chats、messages、rating，并带 observed_at。未提供为 null；0 与缺失不同。source_rating 只保存原站分级 SFW、NSFW、NSFL 或 unknown，不能用本机审核覆盖。

## 4 筛选规则与偏好规则

原站 NSFW 标签只用于内容分类与补货偏好，不代表可以展示露点头像或接受不符合已定内容标准的角色。通过资料筛选和图像检查才可入库；原站标签、头像结论与文字结论分别保存。VL 用于对照资料呈现及角色调性，不能据此声称隐藏人设或聊天效果相同。

| 规则 | 首版行为 |
| --- | --- |
| 基本可用性 | 明确成年证据、真实角色内容与可读取头像；排除未成年设定、工具助手、默认头像、无人像、Q 版简笔角色和无效响应。 |
| 文字内容 | 保留已定的成年非露骨故事资料标准。prompt 至少 200 字符、greet 至少 60 字符为原型最低线，不是 VL 官方标准；九项齐全另作完整率指标。 |
| 图像自动结论 | 允许类型位于模型首位、人像相似度达到 0.23、风险分数不超过 0.1；最小边长 128、灰度标准差 5、边缘强度 1.5。这些是原型默认参数，接入时需用样本复核并版本化。 |
| 不保留人工存疑池 | 有效图像证据下，通过自动入库，不通过自动筛除。下载、缓存、模型运行故障是执行错误，自动冷却重试，不能因此写入永久负面偏好。 |
| 热度门槛 | 原型按首个已知指标判断：浏览 80、消息 100、聊天 30、下载 20、收藏 10、点赞 10；未知热度如实标注。手动标多来的例外按已有规则保留。 |
| 库存比例 | 目标 50 待用加 5 备用；原站 NSFW 目标 80%，女性约 80%，写实角色占总量约 20%。三个比例独立，候选不足时不造数、不改标签。 |
| 补位排序 | 在合格集合内先考虑 NSFW 缺口，再考虑写实缺口和女性缺口，同档按偏好、真实热度及完整度选择；比例无法同时满足时记录实际差距。 |

- 多来：提高相近候选权重，不制造热度，不重复计算同源、同图或同人设的反馈样本。

- 不要此类：直接排除所选角色与重复版本。仅有室友、恋人、哥特等大题材时，只作相似题材降权；包含具体人物类型、特征或拒绝画风时，才按全部条件同时匹配形成跨角色排除。

- 封面多来：独立保存图像参考，通过真实图像向量影响排序，不改变故事题材、不改变原站分级，也不赋予图片安全资格。

- 撤销：只撤销对应事件贡献，不能清空其他反馈。错误扩大范围造成的归档可按现规则恢复；模型淘汰、年龄或内容不合格的角色不得顺带放行。

## 5 库存与自动化状态

建议把角色处理状态、库存位置和任务状态拆开，避免“读取成功”“审核通过”“放进待用”和“已使用”混成一个状态。所有消费者必须由后端事务决定槽位与补位结果。

| 对象 | 状态与转移 |
| --- | --- |
| 角色处理 | discovered → fetching → normalized → screening → eligible。检查不通过进入 rejected，带原因与规则版本；临时故障进入 retry_wait，超出重试进入 failed。 |
| 库存位置 | eligible → ready / reserve / queued。仅 ready 可消费，成功后进入 used。偏好排除进入 archived；删除操作首版不做永久物理清除。 |
| 任务 | queued → running → completed / partial / failed / cancelled。多来源部分失败不抹去成功结果；全部来源失败与正常读取零命中必须区分。 |

| 操作 | 必须满足的约束 |
| --- | --- |
| 消费与补位 | 请求带 Idempotency-Key；同一角色并发消费最多产生一条使用记录。同一备用角色不能同时补两个槽。响应返回 consumed_id、replacement_id、缺口与最新库存修订号。 |
| 导出与查看 | 不改变 ready、reserve、used。批量导出与当前筛选列表一致，缺失字段和失败清单一并输出。 |
| 重复角色 | 同来源原站 ID、规范化链接、图片摘要／像素、人设文本等分层去重；跨来源镜像合并来源关系。不得仅凭同名删除角色。已使用的镜像不能再次补入。 |
| 图片变化 | 重新下载后，只有同一来源且字节未变才复用审核；图片或来源改变则重新检查。失败保留旧缓存并记录重试，不将旧审核套到新图上。 |
| 任务恢复 | 客户端刷新不重开任务；同一工作空间重复开始返回已有活动任务。Worker 租约失效后可由另一执行者恢复，心跳过期不丢游标。 |
| 停止任务 | 停止新读取并丢弃取消后返回的在途提交，已入库内容保留。取消不得清空库存或使用历史。 |

统计口径：read_succeeded 只表示取得详情响应；approved_new 仅统计本轮新读取且通过的唯一角色；reviewed_existing 和 restored 分别统计旧候选复核与恢复。目录候选、完整详情、自动通过、待用新增必须分开，不以旧候选通过数冒充新采集数。

## 6 后端接口与提交协议

下表为建议新增的业务后端契约，路径可按现有系统规范调整，尚未实现。现有 /api/pool、/api/automation 等为本机原型接口，不能原样作为公网服务暴露。推荐复用现有系统鉴权、对象存储、后台任务与监控能力，不强制指定框架或数据库。

| 接口示意 | 用途与关键约束 |
| --- | --- |
| POST /v1/collection/jobs | 创建任务，含 sources、max_read、policy_version；带幂等键，返回 202 和 job_id。 |
| GET /v1/collection/jobs/{id} | 返回任务状态、分来源进度、规则版本、错误与分离后的计数；首版可轮询。 |
| POST /v1/collection/jobs/{id}/cancel | 协作取消，保留已完成数据。 |
| POST /v1/worker/leases | Worker 领取任务或续租；限定工作空间、能力与有效期。 |
| POST /v1/ingestions | Worker 提交角色来源记录，含任务、租约、规范化数据、媒体引用、来源证据与检查证据；重复提交幂等。 |
| POST /v1/media/uploads | 获得受限媒体上传凭证；后端校验摘要、体积、格式与所属工作空间后完成绑定。 |
| GET /v1/characters | 分页查询角色，支持库存位置、来源分级、完整度、性别、媒介、热度与名称筛选。 |
| GET /v1/inventory | 返回目标、实际待用与备用、缺口、比例差距与 revision。 |
| POST /v1/characters/{id}/consume | 原子消费与补位，返回 replacement_id；无候选时返回成功消费加库存缺口，不能伪装补满。 |
| POST /v1/characters/{id}/feedback | 提交 more、less 或 cover_more，带反馈事件 ID、角色版本、规则范围；重复点击不重复累加。 |
| POST /v1/feedback/{event_id}/undo | 按事件撤销并重新计算受影响结果，不删除其他人的反馈。 |
| POST /v1/media/{id}/retry | 重新获取来源图片，重新校验并在内容变化时重新检查。 |

通用契约：时间为带时区的 ISO 8601；长文本走 JSON 字符串，图片走对象存储，不在每次列表轮询返回整份原始页面或图像向量。统一错误含 code、message、retryable、request_id；列表必须分页。401 表示本系统身份失效，来源缺少授权用 SOURCE_AUTH_REQUIRED 单独表达。

## 7 接入约定与页面体验

Worker 上报的是候选与证据，后端负责计算最终业务结论。对服务器执行的来源，可在可信 Worker 中完成模型检查并由后端核验版本与摘要；插件客户端上报的“已通过”不能直接把角色置为 ready。插件只作为接入端，不持有数据库写权限。本机 Worker 也属于客户端上报，后端须重新执行必要的数据校验和图像检查；不能仅凭客户端的模型版本字符串认定审核可信。

| 协议项 | 要求 |
| --- | --- |
| 任务与结果绑定 | 每个提交含 job_id、lease_token、external_source、external_id、source_url、source_version 和 submission_id。后端拒绝过期租约、错工作空间与已取消任务的在途写入。 |
| 版本与幂等 | 幂等范围包含工作空间、接口与业务事件。重复同键同载荷返回原结果，同键不同载荷返回冲突；使用 revision / expected_revision 防止旧响应覆盖新状态。 |
| 来源证据 | 每项字段记录原站路径或可见标签、读取时间和原始对象引用。详情未授权时标 metadata_only，不纳入完整角色或自动入库数。 |
| 媒体提交 | 先申请上传、上传二进制、确认摘要与 MIME，再提交角色引用。服务端媒体解析失败不能只相信文件扩展名。 |
| 权限与凭证 | 复用业务系统登录；Worker 用可撤销且范围受限的身份。来源凭证按来源和操作者隔离，不写入开源配置、导出包或日志。 |
| 网络限制 | 服务器只读取已配置来源与媒体路径；限制体积、超时、重定向和内网地址。来源 401／403 不自动反复重试或伪造授权。 |
| 数据范围 | 首版建议工作空间共享库存与偏好，记录操作者；跨空间角色、图片与反馈均不可越权访问。自定义适配器只能由可信管理员部署。 |

- 列表每行只显示查看、已使用、更多；更多内放多来、不要此类和封面偏好。提交中禁用重复动作，成功或失败给就近短提示。

- 主动操作成功后立即更新列表；后台轮询保留拖选文字保护，操作菜单打开时不得替换该行。旧请求不能覆盖更新的角色、反馈或使用记录。

- 页面展示真实待用数量、备用、使用次数与短任务进度。零库存区分“未开始”“正在读取”“来源失败”“全部被筛除”；筛除原因可展开，提供撤销最近反馈。

- 源站原始分级、已读取字段数和具体失败原因可查看；不在主页面堆叠规则解释、算法阈值或大量重复按钮。

## 8 验收发布与待确认事项

验收必须使用干净工作空间和真实支持来源完成，不能只测接口返回 200。样本分为可稳定复现的固定测试数据与实际联网样本；前者验证规则和事务，后者验证渠道可用性与供给。建议首轮真实试用累计读取 100 份唯一详情并记录完整率、合格率和补位成功率；这是测试计划，不承诺通过数量。

| 编号 | 验收场景与通过条件 |
| --- | --- |
| A01 | 另一台实体电脑上的全新工作空间从分发包启动，不导入原库存、反馈或登录信息；点击一次后自动取得至少一份详情和原图，并有合格角色入库。模型首次安装步骤单独记录。 |
| A02 | 重复开始、刷新、断网恢复和 Worker 重启不创建重复活动任务，不重头扫描已完成目录。 |
| A03 | 角色同源、同图、同设定的跨站重复被挡住，同名但不同角色不误删；已使用镜像不再次出现。 |
| A04 | 两用户并发消费同一角色只记录一次；消费两个角色时不会分配同一个替补。无候选则明确显示缺口。 |
| A05 | 多来改变相似候选排序；不要准确排除本卡与重复版本。连续对多个大题材点不要，不得因此封禁整个目录。撤销不清空其他反馈。 |
| A06 | 图片损坏可恢复，图像变化使旧审核失效；模型故障进入重试，不记为用户不喜欢，不堆积必须人工处理的存疑状态。 |
| A07 | 字段未公开保持空值；SFW 不改为 NSFW；目录、详情、复核、通过、入库计数可逐条追溯。 |
| A08 | 在至少 55 个合格候选的固定数据集中稳定形成 50 待用加 5 备用；导出和查看不消费，10 次连续消费均只产生一次对应记录并正确补位。 |
| A09 | 跨工作空间访问角色、图片、任务、反馈全部被拒绝；日志与导出包不含来源凭证。 |
| A10 | 迁移旧库存后，记录数、作者原文、图片摘要与使用历史可核对；恢复偏好误伤时，明确点过不要的角色与历史不回流。 |

发布顺序：先冻结来源适配器与数据契约，完成后端闭环；再接页面与插件；随后导入一份库存副本核对；通过独立环境试用后小范围接入。保留迁移前备份和旧数据只读副本，回滚不得重置使用记录。

上线前确认：现有后端技术栈与鉴权、工作空间与权限模型、业务角色表和发布入口、可用对象存储与任务能力、来源授权和内容使用范围、部署及试用环境、规则维护责任人。未确认项不由采集器擅自决定。
