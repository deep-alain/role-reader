# 一键自动读取

启动本机服务，点击常备库里的「开始批量读取」，不需要粘贴链接。启动后自动显示「本轮通过」列表，合格角色边读取边出现，可查看完整字段、复制、导出并继续标记「多来／不要」。库存满时明确等待补位。任务在本机后台执行，关闭网页后仍继续；重新打开能看到保存的进度。「停止本轮读取」取消当前批次，已经取得的资料保留。

流程依次执行：

1. 搜索所有启用渠道的目录；NSFW 库存未达目标时优先已验证的 NSFW 来源，每四次保留一次其他渠道轮换。
2. 获取公开完整定义或 PNG 角色卡，保留作者原文与字段来源。
3. 检查明确的成年证据、参考题材、真实热度、非露骨文字，排除重复来源、相同人设、同图及常见裁切。
4. 在本机运行图像风险分类和人像／画风检查；确定通过的自动入库或等待补位，确定不符的筛除，判断不清的移到保留区。
5. 保持 50 个待用和 5 个备用；库存满时建立合格候选缓冲。只有点击「已使用」才消费角色。

默认每批最多实际请求 120 条完整资料，接口允许 1–500。重复点击复用正在执行的任务。单个来源失败不会阻断其他来源。进度区分别展示实际请求数、通过数、进入待用／备用数、疑难数、筛除原因与各渠道错误；通过数可以包含本轮审核通过的历史候选。

疑难头像保留在 `portraitDeferred`，工作台「补货候选」仍可查看和人工确认，不占新的自动读取缓冲。该保留区最多 200 条，更旧的记录归入本机归档，未生成负反馈，也不计作使用。已核验候选缓冲满时结束本轮，等待使用后补位，避免无限爬取。

## 已接通渠道

| 渠道 | 自动任务行为 |
| --- | --- |
| Chub | 目录、公开完整 JSON 定义、头像、热度与真实分级 |
| BotBooru | 目录、公开 PNG 角色卡、头像与来源热度 |
| CharaVault | 目录、公开 PNG 角色卡、头像与来源分级 |
| 自定义适配器 | 按 `config/sources.json` 自动加入完整读取流程 |
| CrushOn / SpicyChat | 自动搜索公开候选目录，完整定义未取得时明确标示授权限制；不计入完整资料或已通过数量 |

不读取账号 Cookie、Token 或作者隐藏定义；401 / 403 会显示原因。原站 NSFW 标签与头像露点是两回事，筛选参数不当成真实返回分级。

## 本机图像检查

首次点击会建立独立环境 `data/vision-runtime`，下载约 240 MB 固定版本的 CPU ONNX 模型；也可提前运行 `python setup_automation.py`。图片不上传到云模型，无付费模型账号要求。下载使用固定版本和 SHA-256 校验，推理成功加载后才显示模型可用。模型、依赖环境、检查证据和缓存都留在本机 `data/`，不打包或提交到仓库。

图像筛选使用两个独立信号：Falconsai 模型的图像风险输出，以及 CLIP 对人像、照片、精细插画、渲染、图标、Q版、线稿等固定描述的相对相似度。CLIP 相似度及分数差不是安全概率。默认只自动通过低风险且人物判断清晰的结果，照片和插画风格不确定时保留为普通人像，不用它凑写实比例。年龄和性别依赖作者公开证据，不从外观推断。

模型也会误判，特别是插画、局部露点或画中画；高风险或低分差结果继续保留待确认。人工已经检查的图片不会被自动结果覆盖。检查绑定图片 SHA 和模型／配置版本，新图片重新检查；模型缺失、下载失败、进程退出或推理超时均不放行。

本轮用 15 张人工通过和 20 张人工拒绝的既有图片做了小规模检查；默认人像边界差值设为 0.020，图像风险上限 0.10。这组样本未出现负例自动通过，但样本非随机、未独立留出，不能当作零误放承诺。

阈值与启用开关在 `config/automation.json`。不要把较低阈值理解为更准确；修改后需要用自己的正反例重新验证。

## 模型出处与许可

- [Falconsai/nsfw_image_detection](https://huggingface.co/Falconsai/nsfw_image_detection)：上游 Apache-2.0。使用 [ONNX Community 转换](https://huggingface.co/onnx-community/nsfw_image_detection-ONNX)，固定版本 `1ceb3c7fe1e9f3f2507e6df577437f23a9149fd5`。转换仓库没有单独许可声明，保留上游出处和模型说明；工具的 MIT 许可不替代模型许可。
- [Xenova/clip-vit-base-patch32](https://huggingface.co/Xenova/clip-vit-base-patch32)：OpenAI CLIP 的 ONNX 转换，固定版本 `d15189d7028b43f1d3e65039190477f6af591c2a`，原版 [MIT 许可](https://github.com/openai/CLIP/blob/main/LICENSE)。
- CPU 推理使用 [ONNX Runtime](https://onnxruntime.ai/docs/get-started/with-python.html)。

## 接口与验证

- `GET /api/automation`：保存的任务、图像模型状态、完整读取与目录渠道列表。
- `GET /api/automation/results`：本轮已通过且仍可用的角色资料，不消耗库存。
- `POST /api/automation/start`：`{"maxRead":120}`，可选 `sources` 指定已配置的完整渠道。
- `POST /api/automation/cancel`：取消本批。

写入接口限本机同源 JSON。自动任务和常规补货共享采集锁，批次运行期间暂停常规网络采集，避免重复请求。完整读取任务的网页进度与角色表格刷新相互独立，选中文字和打开编辑框不会被进度更新打断。
