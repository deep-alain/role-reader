# Role Reader · 角色资料读取器

一个可以自行更换数据渠道的开源角色资料整理工具。Python 标准库本机服务 + 原生 JavaScript 工作台 + Chrome / Edge 扩展，无构建步骤、无付费后端依赖。

## 启动

需要 Python 3.10+ 与 Pillow（用于图片像素去重）。Windows 双击 `启动接口工具.cmd`，或在任意平台运行：

```sh
python -m pip install -r requirements.txt
python api_server.py --no-browser
```

打开 [本机工作台](http://127.0.0.1:8766/app.html)。程序仅监听 127.0.0.1。退出进程后停止补货，重新启动继续使用本机库存。同一个 `data` 目录由进程锁保护；即使用不同端口，也会拒绝第二个写入进程。

## 一键自动读取

点击常备库的「开始批量读取」，自动搜索各启用渠道、获取完整资料、去重、按成年设定与热度筛选，并在本机检查头像。无需粘贴链接。首次使用自动准备约 240 MB 图像模型，之后离线推理。每批最多请求 120 条完整资料，可停止、刷新恢复进度，渠道错误单独显示。启动后自动切到「本轮通过」，边读取边显示合格结果；也可查看进度保留的上一批结果。

疑难头像进入保留区，不占新的读取缓冲；合格角色自动进入待用／备用，满库则等待使用后补位。Chub、BotBooru、CharaVault 和自定义渠道读取完整资料；CrushOn、SpicyChat 自动搜索目录，完整定义仍受授权条件限制，不把目录当完整 Bot。详细流程、模型、阈值与限制见 [自动读取说明](docs/AUTOMATION.md)。

## 能做什么

- 读取角色类别、名称、头像、性别、年龄、Scenario、greet、介绍、prompt；没有公开的字段留空，不自动生成或改写作者设定。
- 后台刷新复用未变化的表格行，拖选文字或打开详情时延后更新；Scenario、greet、介绍、prompt 支持一键复制。
- 「封面多来」单独记录已检查的成年封面参考，用本机 CLIP 的真实图像特征给相近封面加权；不改故事题材的多来／不要，也不计为使用。后续采集和补位会补算候选封面特征；可撤销单张参考。图像相似会受到穿着、构图、画风、配色等因素共同影响，不能当成精确暴露度或安全概率；未审核头像和已排除的类型不会因相似而放行。
- 支持真人／写实风格的补货目标（本机 `data/taste_profile.json` 中的 `targetRealisticPercent`，默认 0 为关闭）。照片／拟真人、插画、渲染与成熟魅力风格分别记录；只在使用后按比例优先补货，不自动替换未使用角色。缺少已核验写实候选时保留实际缺口，不用插画或未核验图凑数。
- “多来／不要此类”会记录题材、已核验画风、人物特征。从此版本起，点击“不要此类”立即持久保存类型排除，按该角色的题材与人物特征组合跨站排除，读取、补货和现有库存统一过滤。组合需同时匹配，已核验不合适画风也可作为排除依据；不会因通用插画、性别等特征把整库封掉。缺少可靠类型时，仅排除此卡及镜像，并如实提示。撤销或改点“多来”会解除对应样本贡献的排除；其他样本仍可继续排除同类。旧反馈保留原效果，可重新点“不要此类”升级为类型排除。重复点击覆盖原票；同图或相同人设的镜像合并为独立样本。“多来”影响相似候选排序、补位选择和三站目录检索；每四次目录读取保留一次原有轮换，自定义适配器仍按原契约读取，所有结果都需通过类型排除。偏好不会绕过成年、人像核验、热度门槛或已设写实比例，缺失指标不补造；反馈和读取均不计为使用。页面展示已排除类型、已学习的样本数、优先／减少的特征及逐条排序依据，学习数据仅保存在本机。
- 常备库目标为 **50 个待用 + 5 个备用**。只点击“已使用”才消费；读取、预览和导出不消费。来源链接、归一化人设和头像像素去重、使用历史与手动编辑内容持久保存。
- 显示真实来源头像。默认图标、没有人物、过淡线稿和 Q 版卡通可排除，精细动漫人物插画可以保留。新图进入候选队列，确认成年、不露点且符合人像风格后才计入待用库存。内置可按需安装的本机 CPU 图像模型，高置信度合格结果可自动通过，疑难结果保留待确认；不会从外观猜年龄。 库存不足时如实显示数量，后台继续取得候选。
- “不要此类”会移出当前角色及符合排除类型的候选，保留淘汰记录，不记作“已使用”。头像检查绑定图片 SHA-256，新图片需要重新检查。同图改名、跨站镜像或仅更换 PNG 角色卡元数据也会去重；保留明确标记多来、字段更完整的版本，同档再参考真实热度。轻微重新压缩通过感知指纹对比；常见正方形等缩略图裁切会与原图对比；大幅裁切或重绘仍不保证识别。
- 已确认成年优先，然后优先原站真实 NSFW 分级，再按成熟人物风格、偏好及同来源真实热度排序。默认 NSFW 库存目标为 80%（40 / 50）；缺少通过核验的候选时展示实际缺口，不把 SFW 或分级未知改成 NSFW。仅自动纳入非露骨成年故事型角色。
- 默认低热度门槛：来源提供浏览量时至少 80；没有浏览量但提供消息数时至少 100。再依次使用聊天 30、下载 20、收藏 / 点赞 10。只使用来源实际提供的第一个指标，缺失保持未知，真实 0 不当成未知。明确点击“多来”可保留个别低热度角色；未知热度会标明，不能称为热门。
- 工作台的“排序规则”可设置额外的浏览、消息、点赞筛选门槛；该筛选只隐藏结果，不删除库存。不同来源的消息、点击、收藏和评分不会换算成浏览量。
- 满库存仍按分钟读取后续候选，候选缓冲上限为 55；新头像仍需核验。后台每 15 分钟检查目录与真实热度，并最多复读 2 个已有角色的完整设定和头像（同条至少间隔 6 小时）。手动编辑字段保留；新头像字节或地址变化后重新核验。
- 编辑先检查成年规则和重复人设，未通过时原记录保留。“导出当前列表”只导出当前筛选及排序结果。“隐藏头像”保留角色和使用状态；“撤销刚才的偏好”可撤销最近一条反馈，镜像与原卡以同一次最新反馈为准。
- 导入 V1 / V2 / V3 JSON、PNG 角色卡及 XLSX / TXT 链接列表，导出 Excel、完整 JSON、失败清单和可选头像。长文本拆分到 Excel 的“长字段”工作表，原文保留在 JSON。

## 自己换渠道

修改 [config/sources.json](config/sources.json)，可关闭、替换内置渠道或加载自己的 Python 适配器。模板在 [adapters/template.py](adapters/template.py)，完整接入约定见 [docs/SOURCES.md](docs/SOURCES.md)。常备库根据配置轮询来源，不需要改前端、导出模块或核心库存逻辑。

内置完整角色卡读取渠道为 Chub、BotBooru、CharaVault。其他来源的完整字段、年龄和授权情况要分别核验，不能把目录元数据当成完整角色卡。CrushOn / SpicyChat 现有接入主要是公开候选元数据；SpicyChat 匿名详情样本返回 401，已登录网页中作者公开的字段可通过浏览器扩展读取。没有读取作者隐藏定义、账号 Cookie 或 Token。

Chrome / Edge 扩展：在扩展管理页加载 `extension` 目录。先正常登录来源站、展开作者公开资料，再从工具栏打开读取器，使用“读取原页面”。扩展按需请求目标站点权限，不处理访问验证或绕过站点限制。

## 本机数据

`data/` 保存库存、历史、偏好和头像缓存，已被 `.gitignore` 排除。公共仓库不分发真实角色库存、作者头像或个人账号信息。内置偏好参数可以在 `taste_profile.py` 的 `LIMITS` 与风格标签中修改，自己的反馈保存在 `data/taste_profile.json`。移动工具时保留 `data/` 即可保留这些记录。
